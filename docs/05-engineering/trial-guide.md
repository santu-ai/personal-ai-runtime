# 14 天试用

这份说明给要在自己的 Windows 电脑上用满 14 天、并判断助手有没有省下核对时间的人。安装包怎么打出来见 [deployment.md](deployment.md)。

## 安装

从发布页下载 Windows 安装包或便携版，安装后打开 Personal AI Runtime。

第一次会进入引导。第一步确认后端已启动。连不上时，引导写出「无法连接后端，请先启动服务」。今天页在整页还没有任何数据时，写出「无法连接到后端服务，请确认后端已启动」，并给出「重试」。

## 接上模型

打开设置里的模型配置。本地试用选「Ollama 本地」，地址用回环（`localhost` 或 `127.0.0.1`，端口一般是 11434）。先在本机把 Ollama 跑起来，再保存。

带邮件、文件或记忆的简报默认只发给本机模型。模型地址不在回环上时，这次简报不会发出。失败会出现在今天页的「失败恢复」里，打开任务后可以重新执行。局域网地址也算出了本机。

## 接上邮箱

设置里展开「Gmail 邮箱配置」。填写 Gmail 地址和应用专用密码，点「保存邮箱配置」，再点「测试连接」。看到「IMAP 正常」就可以给简报用。失败时页面留下原因，核对地址和专用密码后再测一次。

## 接上项目文件

任务页点「新建简报」。对话框标题是「新建项目资料简报」。

- 勾选「读取已配置邮箱」。关键词和最近天数可以填，例如关键词「预算」、最近 7 天。
- 「资料路径（每行一个）」写下要读的文件，例如 `C:\notes\project-a.md`。简报按这些路径读取，不会把整个文件夹扫进来。路径要在允许的目录里，不要指向 `.env`。

填好标题和目标，点「创建」。

## 跑第一份简报

引导的第三步也可以直接选「整理最近邮件」或「核对预算邮件」，创建一份简报并打开任务。

在任务里点「执行」，确认框里点「确认执行」。完成后，今天页「待验收」列出这一份。点进去就是原来的任务。

## 核对来源

交付里每条关键结论带来源编号、位置和片段。状态是「待验收」时，证据还没有经过你核对。摘录对不上来源正文时，不会被当成已经证实。引用里如果原样包含来源中的一段话，片段会改成这一段，状态仍是待核对。

对得上就点「验收」，确认框里可以留一句说明，也可以留空后点「确认验收」。对不上就点「返工」，写下要改的地方，点「确认返工」。旧版还在。

## 读 14 天记录

今天页始终有「14 天试用」，四项是：

| 页面上的名字 | 用来判断什么 |
|---|---|
| 成功率 | 有过评审的简报里，被接受的占多少 |
| 第一版验收率 | 第一次评审就接受第一版的占多少 |
| 人工核对时间 | 从交付到首次评审平均花了多少小时 |
| 每份被接受交付的成本 | 已归因的模型费用，分摊到每份被接受的交付 |

还没有评审、核对或被接受的交付时，分别写「尚无验收」「尚无首次评审」「尚无核对」「尚无被接受的交付」。费用读不成数字时写「未分开计」。这一栏读不到时写「试用记录暂时读不到」，点「重试」。事件较多时写「这段时间事件较多，数字可能不完整」。

点「导出试用记录」会下载一份 JSON。里面有页面上这四句、每一句怎么读，以及接口返回的原始数字。文件名是 `trial-record-` 加导出那天的日期。用这份文件看核对时间和每份成本有没有降下来，而不是只看助手有没有生成文字。
